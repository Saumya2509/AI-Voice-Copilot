# 05. AI voice ordering copilot (no AI API)

Depends on: `03`, `04`. "AI" here means locally trained or rule-based models. No hosted LLM, STT or TTS service is called.

## Pipeline

```
audio -> STT (Vosk WASM) -> transcript
      -> normalize -> language detect -> intent
      -> item candidates -> match + score -> modifiers + quantity
      -> dialogue manager (state, clarify, upsell) -> reply text -> TTS
      -> confirm -> order JSON -> PoS + KOT
```

## 1. Speech to text

- Primary: `vosk-browser` running in a Web Worker with `vosk-model-small-en-in` and `vosk-model-small-hi`. Switch model by selected language, or run both and keep the higher-confidence result for Hinglish.
- Stream partial results to the UI for the live transcript; send only final results to the server.
- Fallback inputs: typed text box and a **sample-call player** that feeds scripted utterances through the same pipeline, so the whole flow can be exercised without a microphone.
- Optional toggle: browser Web Speech API, off by default (see file 02 for the label).
- Add a push-to-talk and an always-listening mode with a simple energy based voice activity detector.

## 2. Normalization (`nlu/normalize.py`)

1. Unicode normalize, lowercase, collapse whitespace.
2. Transliterate Devanagari to a Roman form for matching, and keep the original for display.
3. Replace number words with digits using `numbers.yaml` (`do naan` becomes `2 naan`, `aadha kilo` becomes `0.5 kilo`).
4. Strip fillers from `fillers.yaml`.
5. Expand common contractions and spelling variants (`makhni`, `makhani`, `makhaani`).

## 3. Language detection (`nlu/language.py`)

- Script check: any Devanagari characters mark the utterance as Hindi.
- Else count tokens that appear in a Roman-Hindi stopword list (`hai, kya, mujhe, chahiye, aur, ek, do, nahi`) versus English stopwords.
- Result: `en`, `hi`, or `hinglish` (both above threshold). Keep a per-call language that updates with hysteresis so one stray word does not flip it.
- Replies are produced in the call language; `hinglish` replies use Roman Hindi with English item names.

## 4. Intent recognition (`nlu/intent.py`)

Intents: `greet`, `add_item`, `remove_item`, `modify_item`, `ask_price`, `ask_recommendation`, `ask_availability`, `confirm`, `deny`, `finalize`, `repeat_order`, `give_name`, `give_phone`, `give_address`, `cancel`, `unknown`.

- Train a TF-IDF (char n-grams 2 to 5 plus word n-grams) with logistic regression on templated utterances generated by `train_intent.py` in English, Hindi and Hinglish, with item names and numbers filled from the menu.
- Add rule overrides for high-precision cases: `confirm` for "haan / yes / theek hai / ok / bilkul", `deny` for "nahi / no / rehne do / nahi chahiye", `finalize` for "bas / that's all / ho gaya".
- Store the model with `joblib`; retrain with one command when the menu changes.
- Target 95 percent or higher on the held-out template set and on the hand-written utterances in file 09.

## 5. Item mapping (`nlu/matcher.py`, `nlu/phonetic.py`)

Goal: map a spoken phrase to an item in the PoS database, robustly across accents and spellings.

1. **Candidate spans:** generate 1 to 4 word n-grams from the normalized transcript, excluding quantity and modifier tokens.
2. **Alias hit:** exact match against `aliases.yaml` gives score 1.0.
3. **Phonetic key:** a custom Indic-aware key that collapses `aa/a`, `ee/i`, `oo/u`, `v/w`, `sh/s`, `ph/f`, `th/t`, `dh/d`, doubled letters, and trailing `a/h`. Example: `makhani`, `makhni`, `makhaani` share a key. Matches on key score 0.9.
4. **Fuzzy:** `rapidfuzz.token_set_ratio` and `partial_ratio` against names and aliases; use the better score scaled to 0 to 1.
5. **Character TF-IDF cosine** as a tie breaker for unusual spellings.
6. **Context prior:** items in the current cart, the last item category discussed, and daypart nudge scores slightly (+0.03 at most).
7. **Decision:**
   - Best score at least 0.85 and a clear gap over second place: accept.
   - Best between 0.6 and 0.85, or top two within 0.08: ask a clarification with the top two options.
   - Below 0.6: ask the person to repeat, and offer the category ("Did you want a curry or a bread?").

## 6. Modifiers and quantities (`nlu/modifiers.py`)

Rule based slot filling, attached to the nearest item mention (to the left or right, whichever is closer in tokens).

- **Quantity:** digits, number words, "ek dozen", "pair". Default 1.
- **Size:** `half / full / chhota / bada / regular / small / medium / large`.
- **Spice:** `kam teekha / medium / extra spicy / bina mirch / mild / jain`.
- **Add-ons:** `extra cheese, extra butter, extra gravy, raita on the side`.
- **Exclusions:** `no onion, bina pyaaz, without garlic, no coriander`.
- Validate each modifier against the item's `modifier_groups`. If the request is invalid ("extra cheese" on a dal), say so politely and continue.
- Required modifier groups with no value trigger a short question ("Half or full?").

## 7. Ambiguity clarification

Ask one question at a time, and always give two or three concrete options. Examples (English):

- "Did you mean Paneer Butter Masala or Paneer Tikka Masala?"
- "How many naan, and butter or garlic?"

Never ask about more than one item per turn. Store a `pending_clarification` object so the next utterance ("pehla wala", "the second one", "butter") resolves it. Handle ordinals and short answers.

## 8. Dialogue manager (`dialogue/manager.py`)

States: `GREETING`, `TAKING_ORDER`, `CLARIFYING`, `OFFERING`, `CONFIRMING`, `CAPTURING_DETAILS`, `FINALIZED`, `ABANDONED`.

```
GREETING -> TAKING_ORDER on first add_item
TAKING_ORDER -> CLARIFYING when ambiguity or missing required modifier
CLARIFYING -> TAKING_ORDER when resolved
TAKING_ORDER -> OFFERING when finalize intent or cart stable for one turn
OFFERING -> TAKING_ORDER on accept (item added) or decline (marked declined)
OFFERING -> CONFIRMING when offers done
CONFIRMING -> TAKING_ORDER on "change"; -> CAPTURING_DETAILS on confirm
CAPTURING_DETAILS -> FINALIZED when name and phone (and address if delivery) are present
```

Rules:
- Never upsell in `CLARIFYING`, and not before at least one confirmed item.
- Maximum two offers per call, maximum one per turn. A decline ends upselling for that anchor.
- Offer wording is short and natural, and mentions the benefit ("Garlic naan goes well with that. Add one for ₹60?").
- A combo promotion is offered when the cart contains the combo's anchor and one more item would complete it.
- Always read back a summary before finalizing: items, modifiers, total.
- Handle `repeat_order`, `cancel`, silence (re-prompt after 6 seconds, abandon after 20), and unknown input (ask to rephrase, then offer typed input after two failures).

## 9. Replies and TTS

- Templates in `dialogue/templates.py` keyed by `(intent_or_event, language)`, with placeholders. No generative text.
- Use `speechSynthesis` with `hi-IN` or `en-IN` voices; pick by call language; allow mute.
- Keep replies under 20 words. Hindi and Hinglish templates written to sound spoken, not translated.

## 10. Structured order JSON

Schema in `schemas/order.schema.json`, shared with the client.

```json
{
  "order_id": "ORD-8831",
  "call_id": "call_0192",
  "channel": "phone",
  "language": "hinglish",
  "customer": { "name": "Rohan", "phone": "98XXXXXX10", "address": null },
  "lines": [
    {
      "item_id": 12,
      "name": "Paneer Butter Masala",
      "qty": 1,
      "unit_price": 280,
      "modifiers": [{ "group": "Spice", "name": "Medium", "price_delta": 0 }],
      "notes": "no onion",
      "source": "customer"
    },
    {
      "item_id": 31,
      "name": "Garlic Naan",
      "qty": 4,
      "unit_price": 60,
      "modifiers": [],
      "notes": "",
      "source": "upsell",
      "upsell_rule_id": 77
    }
  ],
  "subtotal": 520,
  "discount": 0,
  "total": 520,
  "upsell": { "shown": 2, "accepted": 1, "added_revenue": 60, "added_margin": 42 },
  "confirmed_at": "2026-10-11T13:42:08Z"
}
```

The `source` field on every line lets the Insights screen separate customer-chosen items from upsold items.

## 11. Finalization and PoS push

1. Recompute totals server side from the database prices.
2. Validate the JSON against the schema; refuse to send if invalid and show the reason.
3. Call `PosAdapter.create_order` with the idempotency key, then `create_kot`.
4. Emit `pos.sent`, then `pos.ack` with the KOT number; update the call record.
5. On failure, retry per file 03 and show a clear state in the UI.

## 12. Languages

- **English, Hindi, Hinglish** are required.
- **Marathi and Gujarati** are optional packs: add aliases, numbers, modifiers and templates in `packs/mr.yaml` and `packs/gu.yaml`. The loader merges packs at start-up and the Settings screen lists the active ones. If a pack has no Vosk model, the language works through typed input and the sample-call player, and the UI says so plainly.

## 13. Privacy

- Audio never leaves the browser in the default mode and is not stored.
- Transcripts are stored with the call for replay, with phone numbers masked.
- A Settings switch deletes stored calls.
